# Agent Safety and Decision Boundaries

The Agentic AI layer is designed to support human maintenance decisions. It operates strictly within predefined safety, logical, and structural boundaries.

## 1. Absolute Prohibitions (What Agents MUST NOT do)
- **Model Integrity:** Agents MUST NOT retrain ML models, modify ML model artifacts, change RF thresholds, change Fusion weights, or override frozen model outputs.
- **Data Integrity:** Agents MUST NOT fabricate sensor values, RUL predictions, failure events, or inventory quantities.
- **Uncertainty:** Agents MUST NOT silently convert uncertainty into certainty. Missing data must be handled explicitly.
- **Action Misrepresentation:** Agents MUST NOT claim a maintenance action was completed when it was only recommended.
- **Safety / Scope:** Agents MUST NOT be used for weapon targeting, weapon control, or offensive decision-making. Their scope is strictly logistics, predictive maintenance, and readiness.

## 2. Tank vs Logistic/Officer Model Isolation
- **Namespace Boundaries:** Agents processing `tank` vehicles must only read data and inference outputs generated by the `tank` model pipeline. Agents processing `logistic_officer` vehicles must only read outputs from the `logistic_officer` pipeline.
- **Cross-Pollination Prevention:** The architecture forbids passing a `tank` telemetry sequence to a `logistic_officer` ML model or using an L/O ML output to determine a `tank` maintenance plan.

## 3. Error and Fallback States
Agents must gracefully handle failures without silently substituting fabricated values.

### A. Missing or Invalid Telemetry
- The Monitoring Agent sets `abnormal_detected = False` and logs a missing-telemetry warning. The pipeline halts for that vehicle instance until valid data arrives.

### B. Unavailable ML Inferences (RF, LSTM, XGBoost, Fusion)
- **RF Unavailable:** The Diagnostics Agent cannot rely on RF classification. It must output `confidence = null` and rely solely on rudimentary sensor threshold breaches (if any) or state `status = UNAVAILABLE`.
- **Prognostic Output Unavailable (LSTM/XGB/Fusion):** The Prognostics Agent sets `fusion_rul_hours = null`. It explicitly explains the missing dependency in its event log and evaluates risk purely on historical degradation (if available). It NEVER invents an RUL.

### C. Insufficient Input Window or Stale Prediction
- If the telemetry sequence is too short (< 30 steps) or the prediction timestamp is stale, the agent rejects the input, marks the prediction as `UNAVAILABLE`, and waits for fresh data.

### D. Unknown or Unsupported Vehicle
- The agent explicitly rejects processing and throws an `UnsupportedVehicleError`. It does not attempt to guess the model family.

### E. Conflicting Agent Outputs
- If upstream agents provide contradictory state (e.g., Monitoring says normal, but a stale Prognostics result says failure imminent), the Orchestrator/Maintenance Planning Agent flags a conflict, demotes the confidence level, and recommends human review.
