# VEDA Prognostics Agent

## 1. Purpose
The Prognostics Agent interprets and communicates the Remaining Useful Life (RUL) predictions generated by the upstream frozen ML pipeline. It acts as the third stage in the Agentic AI pipeline.

The Prognostics Agent is **STRICTLY an interpretation layer**. It does **NOT**:
- Perform inference as an independent RUL model.
- Calculate a new RUL formula or override the frozen `Fusion_RUL`.
- Fabricate degradation rates or confidence scores.
- Consume ground-truth RUL (preventing target leakage).

## 2. Upstream Dependencies & Approved RUL Source
The agent depends on the `Fusion_RUL` generated by the frozen Fusion V2 artifact (e.g., `0.30 × LSTM_RUL + 0.70 × XGB_RUL`). 
The `Fusion_RUL` is treated as the singular authoritative prognostic estimate. Individual model outputs (`LSTM_RUL`, `XGB_RUL`) may be passed through for context but are never independently re-averaged by this agent.

## 3. Inputs
The agent expects a strictly typed `PrognosticsInput` schema:
- `monitoring_result` (`MonitoringResult` object)
- `diagnostics_result` (`DiagnosticsResult` object, optional)
- `lstm_rul_hours` (float, optional)
- `xgb_rul_hours` (float, optional)
- `fusion_rul_hours` (float, optional)

*All inputs are validated using Pydantic. Any inclusion of prohibited fields (like `Actual_RUL`) will be rejected.*

## 4. Outputs
The agent returns a `PrognosticsResult`:
- `vehicle_id`
- `timestamp`
- `fusion_rul_hours` (Passed through exactly, or explicitly marked missing)
- `lstm_rul_hours`
- `xgb_rul_hours`
- `degradation_trend` (string: "OBSERVED_DEGRADATION", "STABLE", "UNKNOWN")
- `risk_level` (string: "NORMAL", "WARNING", "CRITICAL", "UNKNOWN")
- `status` (string: "AVAILABLE", "PARTIAL_MODELS_AVAILABLE", "UNAVAILABLE", "INVALID", "CONFLICT")
- `execution_metadata`

## 5. Decision Logic & Error States
- **Invalid Upstream State:** If monitoring or diagnostics flagged `UNSUPPORTED_VEHICLE`, `INSUFFICIENT_DATA`, or `CONFLICT`, the Prognostics Agent carries this forward, setting its own status to `INVALID` or `CONFLICT`.
- **RUL Validation:** The agent validates that the RUL is numeric, positive, and finite. If an RUL value (e.g., NaN or infinity) is passed, it explicitly drops it and changes status to `UNAVAILABLE`.
- **Missing Fusion:** If `fusion_rul_hours` is missing but other models exist, it sets status to `PARTIAL_MODELS_AVAILABLE` but does **not** recalculate fusion.

## 6. Vehicle Isolation
The shared schema logic applies generically to Tank and Logistic/Officer vehicles. The isolation is guaranteed by the orchestration layer feeding strictly namespace-isolated model outputs into the agent.

## 7. Test Coverage
Unit tests (`tests/test_prognostics_agent.py`) verify:
- Exact propagation of the authoritative `Fusion_RUL`.
- Strict prohibition of RUL recalculation or threshold invention.
- Handling of NaN/Infinity/negative RUL edge cases.
- Preservation of upstream conflict and invalidation signals.
