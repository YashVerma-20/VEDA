# VEDA Spare Parts Agent

## 1. Purpose
The Spare Parts Agent translates approved maintenance recommendations into structured spare-parts requirements. It acts as the fifth stage in the Agentic AI pipeline.

The Spare Parts Agent does **NOT**:
- Invent part numbers or quantities.
- Fabricate supplier information or procurement status.
- Place orders or modify inventory records.
- Assert stock availability without an approved data source.

## 2. Upstream Dependencies
The agent depends on the `MaintenancePlan` generated by the upstream Maintenance Planning Agent. It evaluates whether a maintenance action requires spare parts and coordinates part requirements accordingly.

## 3. Inventory and Part Mapping Boundaries
**CRITICAL NOTE:** At this stage in the project architecture, there is **NO** approved inventory database service and **NO** approved part-mapping configuration.

Consequently, the agent operates under strict constraints:
- `inventory_status`: Always defaults to `UNKNOWN` or `NOT_APPLICABLE`.
- `part_identifier`: Remains `UNKNOWN` or generic, explicitly refusing to hallucinate SKUs.
- `quantity`: Remains `None` (unspecified) because there is no explicit rule dictating component volume.
- `procurement_status`: Always `UNKNOWN`.

## 4. Inputs
The agent expects a strictly typed `SparePartsInput` schema:
- `maintenance_plan` (`MaintenancePlan` object)

*Inputs are strictly validated. Missing or invalid plans result in an explicit conflict/unknown response.*

## 5. Outputs
The agent returns a `SparePartsRequirement`:
- `vehicle_id`
- `timestamp`
- `maintenance_reference` (string)
- `component` (string: extracted from logic if possible, else "UNKNOWN")
- `part_identifier` (string: "PART_MAPPING_UNAVAILABLE" or "NOT_APPLICABLE")
- `quantity` (Optional[int]: `None`)
- `inventory_status` (string: "UNKNOWN" or "NOT_APPLICABLE")
- `procurement_status` (string: "UNKNOWN")
- `availability_status` (string: "UNKNOWN")
- `reason` (string: clear explanation of missing data sources)
- `source_information` (dict indicating false for mapping/inventory availability)
- `execution_metadata`

## 6. Error & Conflict Handling
- If the upstream maintenance plan is flagged as `CONFLICT` or `INVALID`, the Spare Parts Agent propagates this by setting all statuses to `UNKNOWN` with the reason pointing to upstream conflicts.
- If the maintenance plan states `UNKNOWN` for its own recommendation, spare parts are returned as `NOT_APPLICABLE`.

## 7. Vehicle Isolation & ML Boundary
The agent processes purely logical schemas. It cannot directly touch ML outputs, and the orchestration layer guarantees Tank and Logistic/Officer isolation. No RUL, Thresholds, or ML weights can be evaluated or modified by this agent.

## 8. Test Coverage
Unit tests (`tests/test_spare_parts_agent.py`) verify:
- Complete refusal to fabricate part identifiers and inventory counts.
- Semantic distinction between "UNKNOWN" (missing data source) and "NOT_APPLICABLE" (no maintenance needed).
- Accurate propagation of upstream conflict/invalid states.
